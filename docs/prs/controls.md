# feat/controls — T-145 stable control ids

## What / why
Foundation for MIDI (APC40 mkII and generic controllers), OSC and timeline
envelopes: every control has a stable id and one entry point.
- `studio/src/controls.rs`: registry (205 controls today) — `master.size`,
  `master.brightness`, `master.rotation_speed`, `audio.*`,
  `transport.blackout`, `transport.arm` (not external), `page.next/prev/<n>`,
  `grid.<page>.<row>.<col>` (5×8 per page, APC40 grid). `live.<param>` is
  an alias of `master.<param>`. `apply(id, value|norm)`; `current()` for
  feedback.
- Shared state now tracks `cue_page` and `active_cue` server-side, so a
  MIDI page/cue change shows up in the UI (the preview loop follows them).
- API: `GET /api/controls`, `POST /api/control`, `GET /api/control-values`.
  `/api/control` is treated as external: it can't arm the laser (403);
  arming stays on `/api/arm` (button / Space).
- `--list-controls` prints the table; `docs/controls.md` is regenerated by
  a unit test.
- UI: control ids as tooltips; page tabs go through `page.<n>`.

## Testing
- 52 unit tests (unique ids, norm↔value bounds, clamping, unknown ids →
  error, arm refused externally, blackout always allowed, grid cells play
  the right cue, pages wrap, cue keeps brightness). Clippy `-D warnings`
  clean.
- API on a throwaway instance (port 8093): size/grid/page/audio → 200,
  unknown → 404, arm → 403 and stays disarmed.

## Risks / follow-ups
- Sliders don't yet follow master values changed from MIDI (T-143 panel).
- Controls for T-140/T-141/T-150 (live modifiers, colour, tempo) get added
  by those tasks.
