## Contexte
Sur macOS, une capture refusée renvoie souvent du silence sans erreur : l'utilisateur croit que le laser « ne marche pas ».

## À faire
- Détecter une entrée *exactement* nulle pendant > 2 s alors que la capture est active → état *Autorisation refusée ?* avec message d'aide (Réglages Système › Confidentialité et sécurité › Microphone, activer le terminal utilisé ; `tccutil reset Microphone` pour redemander).
- Distinguer : aucun appareil, appareil disparu, silence réel (bruit de fond présent), signal saturé (crêtes ≥ −0,5 dBFS → *Entrée trop forte*), signal trop faible (< −45 dBFS en moyenne → *Entrée trop faible*).
- Préparer l'empaquetage futur : documenter `NSMicrophoneUsageDescription` et l'entitlement `com.apple.security.device.audio-input` dans `docs/` (sans créer le paquet).

## Modèle de données
```rust
pub enum InputHealth { Ok, NoDevice, DeviceLost, PermissionSuspected, TooQuiet, Clipping, Silent }
```

## Interface
Pastille d'état à côté du vumètre (vert/orange/rouge) avec texte en français et lien d'aide ; zone cible −25..0 dBFS marquée sur le vumètre.

## Critères d'acceptation
- [ ] Source de test qui renvoie des zéros exacts : *Autorisation refusée ?* en ≤ 3 s
- [ ] Bruit à −70 dBFS : *Silence* (pas *Autorisation refusée ?*)
- [ ] Sinus à 0 dBFS : *Entrée trop forte*
