## Contexte
Un nom ne suffit pas pour reconnaître un look dans le noir : les pros affichent une vignette dans chaque case. Des vignettes animées rendent la grille lisible d'un coup d'œil.

## À faire
- Nouvelle route `GET /api/cue-thumb?id=<id>&t=<s>` : calcule hors du thread moteur une image du cue à l'instant `t` (Animator dédié, sans toucher à l'état en direct), réduite à ≤ 300 points, et la renvoie en JSON comme `/api/frame`.
- Côté UI : un petit canvas par case, dessiné avec la même fonction que l'aperçu 2D (version sans halo). Animation lente (une image toutes les 250 ms, 8 images en boucle mises en cache par cue).
- Cache côté client par id ; seules les cases visibles sont animées ; pause quand l'onglet n'est pas visible.
- Réglage *Vignettes : animées / fixes / aucune*.

## Modèle de données
Pas de nouveau modèle persistant. `ThumbRequest { id: String, t: f32 }` ; plafond 300 points.

## Interface
Libellés : *Vignettes*, *Animées*, *Fixes*, *Aucune* (onglet *Réglages*).

## Critères d'acceptation
- [ ] Chaque case pleine affiche une vignette reconnaissable du look
- [ ] Appeler `/api/cue-thumb` ne change pas `/api/frame` ni le cue actif
- [ ] Avec 40 vignettes animées, les images/s de l'aperçu principal ne baissent pas de plus de 5 %
- [ ] *Aucune* supprime tous les canvas de vignettes

## Tests
Unitaires : `cue-thumb` renvoie ≤ 300 points et n'altère pas l'Animator principal. e2e : présence d'un canvas par case, bascule *Aucune*.

## Notes
Les vignettes n'ont aucun lien avec la sortie laser (jamais envoyées au DAC). Règles de CLAUDE.md : laser désarmé au démarrage, Échap = blackout instantané, sécurité appliquée en dernier (après calibration), tests en aperçu uniquement (jamais `--device`). Propriété intellectuelle : concepts inspirés de la doc publique Pangolin/Laserworld et des visualiseurs du marché, rien de copié (ni captures d'écran, ni icônes, ni noms d'effets, ni contenus).
