## Contexte
Pour apprendre la disposition et vérifier les affectations sans deviner :
un schéma de l'APC40 dans l'onglet Contrôleur qui montre ce que fait chaque
bouton, s'allume comme le vrai, et permet de cliquer (utile aussi sans
contrôleur branché et pour les tests e2e).

## À faire
- Dessin SVG maison (pas d'image Akai ni de schéma BEYOND/Showcontroller) de
  l'APC40 / mkII selon le modèle détecté : grille 5×8, Scene Launch, Clip Stop,
  boutons de piste, faders, potards, transport, Shift, Tap.
- Chaque élément affiche au survol son affectation (libellé français de la
  cible T-145, « Shift : … ») et le message MIDI (« Note 0x52 »).
- Couleurs des pads et LED = état LED calculé par T-205/T-206 (lu via
  `GET /api/midi/leds`, ~10 Hz quand l'onglet est visible).
- Clic sur un élément = injecte l'action correspondante (même chemin que le
  matériel), Shift virtuel verrouillable.
- Clic droit sur un élément = « Apprendre ici » (associer ce bouton du schéma
  à un contrôle) ou « Retirer l'affectation ».
- Bouton « Exporter la disposition » : télécharge le profil JSON actif.

## Modèle de données
`GET /api/midi/leds` → `{ port, model, leds: { "<note|cc>:<canal>": valeur } }`.

## Interface
Onglet « Contrôleur » : schéma en haut, liste des affectations (T-203)
dessous. Libellés : « Disposition », « Shift verrouillé », « Exporter la
disposition ». Le schéma doit tenir en largeur 1280 px sans défilement.

## Critères d'acceptation
- [ ] Sans contrôleur, cliquer un pad du schéma joue la cue correspondante.
- [ ] Le pad de la cue active est vert (APC40) ou de la couleur de la cue (mkII) sur le schéma.
- [ ] Le survol d'un fader indique « Fader 1 — Taille ».
- [ ] Le profil exporté se réimporte à l'identique.

## Tests
- e2e : studio `--no-midi --midi-test`, clic sur le pad (0,0) du schéma → `/api/state` montre la cue 1 de la page ; survol → info-bulle attendue.
