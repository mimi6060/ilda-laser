## Contexte
Les agents et la CI n'ont pas d'APC40, et ne doivent jamais toucher celui de
l'utilisateur. Il faut pouvoir tester tout le MIDI (détection, mappings, LED)
avec un appareil simulé.

## À faire
- **APC simulé** (`midi::testing::FakeApc { model }`, `#[cfg(test)]` ou
  module `testing` public) : produit les octets d'un appui de pad (ligne,
  colonne), d'un fader, d'un encodeur, de Shift, répond à la Device Inquiry
  avec `0x73` ou `0x29`, et enregistre les octets LED reçus pour les
  vérifier (« le pad (0,0) est vert ? »).
- **Ports virtuels CoreMIDI** (`midir::os::unix::VirtualInput/VirtualOutput`)
  pour un test d'intégration « vrai CoreMIDI » : le studio voit apparaître un
  port « Laser Studio Test APC40 mkII », le détecte, reçoit un pad, envoie une
  LED. Marqué `#[ignore]` par défaut si CoreMIDI indisponible, lancé
  explicitement (`cargo test -p laser-studio -- --ignored midi_virtual`).
- **Mode test HTTP** : option CLI `--midi-test` (avec `--no-midi`) qui ajoute
  un appareil fictif et `POST /api/midi/inject { port, bytes: [..] }` (octets
  bruts) + `GET /api/midi/sent` (octets LED « envoyés » à l'appareil fictif).
  Refusé (404) sans `--midi-test`.
- Helper e2e Playwright `midi.js` : `pressPad(r,c)`, `moveFader(n, v)`,
  `turnKnob(cc, delta)`, `ledAt(r,c)`.
- Mettre à jour `studio/e2e` pour lancer le studio avec `--no-midi --midi-test`.

## Modèle de données
`FakeApc { model: Model, received: Vec<Vec<u8>> }` ; appareil fictif `MidiDevice { name: "Test APC40 mkII", model: Apc40Mk2, fake: true }`.

## Interface
Aucune (outillage de test).

## Critères d'acceptation
- [ ] `cargo test -p laser-studio` couvre détection, mapping et LED avec le faux APC (sans matériel, sans port réel).
- [ ] `/api/midi/inject` n'existe pas sans `--midi-test`.
- [ ] Un test e2e appuie sur un pad simulé et voit la cue changer dans `/api/state` et la LED dans `/api/midi/sent`.
- [ ] Aucun test n'ouvre un port MIDI réel ni n'utilise `--device`.
