## Contexte
Sans mesure, on règle les seuils au hasard. Il faut un banc reproductible pour les onsets, le BPM, les sections et la latence.

## À faire
- `studio/src/audio/testsig.rs` (cfg(test) ou module de test) : générateurs de kick, caisse, charleston, clics, lignes de basse, montée (bruit filtré), silence, changements de tempo, avec vérité terrain.
- Métriques réécrites (inspirées de mir_eval, MIT) : F-mesure d'onsets ±50 ms, précision BPM Acc1 (±4 %) et Acc2 (octaves), F-mesure des temps ±70 ms, temps de verrouillage, latence transitoire → événement.
- Commande `cargo test -p laser-studio audio_bench -- --ignored --nocapture` qui imprime un tableau de résultats.
- Corpus réel optionnel hors dépôt (`--corpus <dossier>` avec fichiers WAV + annotations CSV) : enregistrements de l'utilisateur ou morceaux dont la licence le permet ; jamais commités sans licence compatible (`docs/CONTENT_SOURCES.md`).

## Modèle de données
```rust
pub struct BenchResult { pub onset_f: f32, pub kick_f: f32, pub bpm_acc1: f32, pub bpm_acc2: f32, pub beat_f: f32,
    pub lock_time_s: f32, pub latency_ms: f32 }
```

## Interface
Aucune interface (outil de développement).

## Critères d'acceptation
- [ ] Le banc tourne sans matériel audio ni réseau
- [ ] Il sort un tableau lisible et échoue si une métrique passe sous le seuil fixé dans le test
- [ ] Seuils initiaux documentés dans la note de PR et référencés par T-232/T-233

## Tests
Le banc est lui-même un test ; il doit être déterministe (graine fixe pour le bruit).

## Notes
Des outils GPL (aubio, etc.) peuvent servir **hors du dépôt** à produire des annotations de référence, jamais être liés ou copiés. Règles de CLAUDE.md : laser désarmé au démarrage, Échap = blackout instantané, sécurité appliquée en dernier (après calibration), tests en aperçu uniquement (jamais `--device`). Licences : aucune dépendance GPL/AGPL dans le build par défaut (aubio, essentia, BTrack exclus) ; algorithmes réécrits depuis les publications, voir docs/research/audio-analysis.md §4.
