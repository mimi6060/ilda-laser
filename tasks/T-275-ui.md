## Contexte
Pour concevoir des looks de faisceaux festival sans laser ni brume, il faut voir les faisceaux en perspective depuis le public, comme les aperçus 3D de BEYOND/QuickShow 5.5, Depence ou Capture. L'aperçu 2D actuel montre un éventail de 8 faisceaux comme 8 points.

## À faire
- Choisir la base technique par un court essai et le noter dans le Journal : **three.js vendu localement** (recommandé : `three.module.min.js` + `OrbitControls` figés à une version, servis par `web.rs` via `include_bytes!` sous `/vendor/…`, chargés par `importmap`) ou WebGL2 brut. Pas de chargement depuis un CDN à l'exécution : le studio doit marcher hors ligne en salle.
- Onglet *3D* de la Scène (T-270 ; si T-270 n'est pas fait, un bouton *Vue 3D* au-dessus du canvas) : salle boîte (sol, murs, plafond en fil de fer sombre), un projecteur par défaut au bord de scène à 3 m de haut, orienté vers le public.
- Conversion : point `(x, y)` de l'image finale (après calibration et sécurité, la même que `/api/frame`) → direction `yaw = x·θ/2`, `pitch = y·θ/2` (θ = angle de scan, défaut 40°), rayon intersecté avec la boîte → segment projecteur → impact.
- Dessin simple : une ligne par point allumé, mélange additif, `depthWrite = false`, couleur RGB du point.
- Caméra orbitale (souris, trackpad, tactile) autour du centre de la salle ; double-clic = recentrer.
- Boucle `requestAnimationFrame` ; données lues à 30 Hz depuis `/api/frame` (réutiliser la boucle existante, pas de deuxième requête) ; pause quand l'onglet 3D n'est pas affiché.
- Sans WebGL2 : message *Visualiseur 3D indisponible sur ce navigateur* et l'onglet 2D reste utilisable.

## Modèle de données
Côté UI uniquement dans cette tâche : `{ projector: { pos:[x,y,z], yaw, pitch, roll, scanDeg }, room: { w, d, h } }` codés en dur (le modèle persistant est T-277). Typed arrays (`Float32Array`) réutilisés d'une image à l'autre, pas d'objet par point.

## Interface
Libellés : *3D*, *Recentrer*, *Visualiseur 3D indisponible sur ce navigateur*. Astuce affichée : *Glisser pour tourner, molette pour zoomer, Maj+glisser pour déplacer*.

## Critères d'acceptation
- [x] Un cue « éventail » intégré apparaît comme des faisceaux divergents depuis le projecteur jusqu'au mur du fond
- [x] Un point en (0,0) produit un faisceau horizontal droit devant (test visuel + test unitaire de la fonction de conversion)
- [x] 60 images/s d'affichage avec 3 000 points sur un Mac M-series (mesure notée dans le Journal)
- [x] Le studio fonctionne sans accès Internet (aucune requête vers un domaine externe, vérifié dans l'e2e)
- [x] La bibliothèque vendue est listée dans `docs/CONTENT_SOURCES.md` (URL, licence MIT, date)

## Tests
JS pur testable : fonctions `pointToDir` et `rayBox` dans un module séparé ; tests e2e qui les importent via `page.evaluate`. e2e : onglet 3D visible, canvas WebGL présent, aucune requête réseau externe (`page.on('request')`).

## Notes
Le visualiseur lit la même image finale que le DAC et n'a aucun chemin de sortie : il ne peut ni armer ni envoyer. Licence three.js (MIT) à vérifier et consigner avant l'ajout. Règles de CLAUDE.md : laser désarmé au démarrage, Échap = blackout instantané, sécurité appliquée en dernier (après calibration), tests en aperçu uniquement (jamais `--device`). Propriété intellectuelle : concepts inspirés de la doc publique Pangolin/Laserworld et des visualiseurs du marché, rien de copié (ni captures d'écran, ni icônes, ni noms d'effets, ni contenus).
